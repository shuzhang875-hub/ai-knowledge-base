# 体检办法
先按全局入口解析固定知识库，在该库内逐项实际检查；入口失效时停止，不在当前项目另建库。只读外部链接的文字，不为体检访问外部网站或安装依赖。
1. 遍历 Markdown（跳过隐藏配置、依赖、缓存）。检查本地 Markdown 链接和 Obsidian 双链：URL 解码、相对路径、文件存在性和标题锚点；资源和图片同样检查。外部网址明确列为未做联网验证，不称“全部链接已通过”。能唯一确认新位置的修正，找不到/多候选的列“待确认”，不猜链接。
2. 按 UTF-8 文件字节数检查 >30KB（30,720 字节）的页。仅把过程流水账、旧记录原文拆到同目录同名“-历史.md”（已有就追加并防重复），当前页留相对链接；历史页过大可按年月拆分并有索引。不把仍填数据的表、当前规则、有效决定、其他文件规定要从此页读取的内容搬走。移走段落含相对链接时保持有效，校验条目数和原文没有丢。大页若全是当前内容不强拆，报告保留原因。
3. 逐行读《现在看这里》所指的项目卡，比正文更新日期和当前状态、采用文件、下一步。导航仅保留稳定入口，重复状态按唯一主记录改成链接；不以文件修改时间或末尾历史日期替代当前事实。不知道哪个版本算数就标“待确认”，不要自定。未指向项目卡的行注明不适用。
4. 读灵感库的知识库卡点.md 和相关项目已验证的复盘，复查同类卡点是否再出现；仅把已确认且范围明确的做法写入对应规矩，新业务决定待确认。已确认的入口补进导航或对应分区 README；导航保持短，细节用链接。一条也没有就如实说明。
5. 列出全库所有未解决的“待确认”（含“待本人确认”）事项，给相对路径和原句；规则示例里的字样、明确已解决和历史原话区别列出，不冒充待办。不能自动确认事实。
6. 保存“知识库体检-日期.md”，同日再跑用序号，不覆盖旧报告。列每项发现、改过的文件、未解决项。报告里的汇总不作为下一次的新问题反复收录。
7. 复查变更后的链接、拆分原文和当前事实。告诉用户“整理了哪里／哪些待确认／哪些没有改及原因”。不删除任何资料、不改变用户定下的事。
